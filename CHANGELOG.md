# Changelog

## Unreleased

- A GIF of `sail_together` in the README (`assets/sail_together.gif`), made by `make_gifs` from the real game; the rasteriser now draws the half blocks of the pixel layer.
- **Multiplayer (phase 6).** `game::Sim` is the rules of a game apart from its picture (`type Input: Encode + Decode + Clone + Default`, `step(&mut self, inputs, rng)`, `hash`), and `game::Lockstep` plays one `Sim` on several machines by sharing only each player's input: an input delay (3 steps by default), the latest inputs resent in every packet so a link that drops or reorders heals itself, a stall (`Progress::Stalled { waiting_for }`) instead of a guess when an input is late, at most four steps of catching up per update, and a hash of the state compared every 60 steps so a game that drifts apart is reported as `Progress::Desync` with the step it happened between. A player who leaves or goes silent is `Progress::Lost`.
- `game::Transport` (`send`, `poll`, `is_open`) with `Local` (in-process, for tests and hot-seat) and `Tcp` (`std::net`, non-blocking, length-prefixed messages, a star around the host: `Host::bind(addr)?.accept(players, timeout)` and `Tcp::join(addr, timeout)`). `game::announce` and `await_message` share the seed and settings before a match. A WebSocket transport for the browser is not built yet.
- `game::Encode`, `Decode`, `Reader` and `DecodeError`: hand-written little-endian bytes (no serde) for integers, `f32`, `bool`, `Option`, tuples, arrays, `Vec` and `String`; bad bytes are an error, never a panic. `game::Hasher` is FNV-1a 64 for state hashes. `game::PlayerId`, `PeerId`, and `Context::players` and `Context::me` (1 and player 0 in local play).
- `game::math::{sin, cos, exp}` use only basic IEEE operations, so they give the same bits on every machine, which `f32::sin` does not promise. `Waves` uses them. Inside a `Sim`, use these instead of the `f32` methods.
- `Screen::blit` copies one `Screen` onto another at an offset, to draw a fixed-size world into any window.
- `cargo run --example sail_together -- host 2` / `-- join HOST:7777`: `sail` for two to four players over TCP lockstep, each in a boat of their own, on a sea as big as the host's window. `sail` itself is now split into `SailSim` (the rules, any number of boats, deterministic) and a view (sparks, steam and spray with their own random numbers), so the random streams are separate: a seeded solo round plays a little differently from before, while the boat, the time and the sea are bit-identical with no fireballs.
- **The website has three pages.** `/` is a landing page with two doors, Terminal Art at `/art/` and Terminal Games at `/games/`; old share links (`/#code=...`) are forwarded to `/art/#code=...`. All pages share one top bar (ART, GAMES, GitHub, crates.io) and the same retro look. `examples/build_site.rs` is split: the shared style, nav, rainbow title and colour classes are in `examples/site/shell.rs`, and each page has its own module (`art_page.rs`, `landing.rs`, `games_page.rs`).
- **The games page plays the real games.** `examples/web_games.rs` is a second WebAssembly module (so the art page does not download game code) that drives `glow`, `sail` and `quickgame` through `Headless`: the page forwards key down and up events and the pointer, and paints the cells on a canvas, drawing half blocks as rectangles. It has touch buttons for phones, shows the game's real source beside it, a short "make your own" section, a tuner with sliders, and says plainly that multiplayer is not on the page yet.
- `game::Tuning` and `game::Knob`: numbers a game exposes (`Tuning::new().knob(name, label, default, min, max)`, read with `tuning.get(name, fallback)`) so a web page can change them while the game runs, with no interpreter. `glow` exposes `mote_rate` and `round_length`; `sail` exposes `fireball_rate`, `wave_height` and `boat_speed`. Each game has `pub fn tuning()` and `pub fn start(tuning)`; with the default values they play exactly as before.
- `Headless::mouse` feeds any mouse event (button down and up, drag) to the game, so a held button can be tested.
- `cargo test` now also runs the tests of `build_site` and `check_site`, which were not run before.
- `check_site` loads `/`, `/art/` and `/games/`, checks that an old `/#code=...` link is forwarded, starts a game, presses a key and sees the frame change, drags a slider and presses the touch buttons.
- `sail: the sea sits lower, fireballs fall a little slower and the boat sails a little faster; overlays are drawn in framed panels (new Screen::frame and clear_pixels).`
- `Screen::pixel`, `disc`, `glow`, `finish_frame` and `PixelArt`: games draw objects as coloured regions (half-block pixels and soft glows) instead of text characters; `Particles` now draw as coloured pixels. `run` and `Headless` finish each frame for you.
- `cargo run --example sail`: the flagship game: a sailboat that steers left and right, dodging fireballs that fall from the sky and fizzle out in steam when they reach the water. The sea grows rougher the farther you sail, and the sky runs from dawn to night.
- `game::Waves` (one sea function for both the picture and the physics: `height`, `slope`, `surface_y`, `tilt` and `shade`, with `calm` and `stormy` presets) and `game::Particles` (pooled bursts, sparks and spray: `emit`, `burst`, `gravity`, `drag`, `palette`, `step` and `draw`, with no allocation after construction).
- `Screen::backdrop` and `Screen::backdrop_in`: draw art formulas as the background of a game, or into a part of the screen.
- `llms.txt`, README and CONTRIBUTING cover the games section; new example quickgame.
- `cargo run --example glow`: a game of light and plasma (title, play, pause and game-over scenes; the sky ripples when you collect motes).
- `glow` now draws its light, motes and trail as glowing coloured regions instead of text characters.
- `game::Game`, `Next`, `Context`, `Headless` and `run`: the scene-based game loop (fixed 60 updates a second, scenes for menus and pause, a headless runner for tests, Ctrl+C always quits and q/Esc belong to the game).
- `game::Rng` (deterministic random numbers, the same on every machine), `game::Timer` (cooldowns and spawn clocks in seconds of game time), `game::Pool` (fixed-capacity object lists that never reallocate) and `game::Hit` (rectangle and circle collision tests).
- `game::Screen` (a drawing surface with text, fills, bars and sprites, all clipped to the screen so nothing panics off screen) and `game::Sprite` (pictures from string literals, with transparent spaces, two-colour `paint` and `flipped` mirroring).
- `game::Keys` (held, pressed and released keys, with timing-based fallback: a press is held for 300 ms, each OS repeat extends it by 100 ms, and real releases from the kitty protocol end it at once) and `game::Controls` (named actions bound to keys, so players can rebind them). Pure logic with an injected clock, so it is tested with no terminal.
- `Event::KeyUp(Key)` and parsing of the kitty keyboard protocol: key release events from terminals that support it (kitty, WezTerm, Ghostty, foot, Alacritty, iTerm2, recent Windows Terminal), with key repeats still arriving as `Event::Key`. `Terminal::enable_key_release` turns it on.
- `Terminal::enable_key_release` (kitty keyboard protocol key-release events where the terminal supports it; it asks first and returns `false` otherwise) and `Terminal::has_key_release`.
- `cargo run --example events -- --key-release` shows key press and release events on terminals that support them.
- `Terminal::draw` now sends only the cells that changed; the first call draws everything. New public `Renderer` writes diffed frames to any `Write` (`Renderer::draw_to`, `Renderer::invalidate`). `cargo bench --bench render` compares it with a full redraw; see the README.
- `Terminal`: an interactive session. `Terminal::start()` enters raw mode,
  turns on mouse reporting and hides the cursor, and reads input on a
  background thread; `poll(timeout)` and `wait()` return events. Everything is
  undone on drop. A lone Escape byte becomes the Escape key after 25 ms.
- `Parser`: incremental parser for terminal input (characters, UTF-8, control
  keys, arrows, navigation and function keys, Shift/Alt/Ctrl modifiers, SGR
  mouse press, release, drag, move and scroll). `Parser::has_pending`.
- `RawMode`: raw terminal mode guard for Unix and Windows, restored on drop.
  `MOUSE_ON` and `MOUSE_OFF` escape sequences.
- `cargo run --example events` prints events live.
- `cargo bench` parser benchmarks.
- Re-exports `terminal_graphics`.
- End-to-end tests on Windows (`tests/e2e_windows.rs`): the `events` example runs in a ConPTY pseudo console and is fed raw key and mouse sequences.
- Shared end-to-end scenarios (`tests/support`) and a Unix pty harness (`tests/e2e_unix.rs`), plus a CI workflow running the suite on Ubuntu, macOS and Windows and a Rust 1.70 check.
- `Terminal` now uses the alternate screen and finds the window size by asking the terminal (`Terminal::size`), falling back to 80x24. `Terminal::draw(&display)` shows a `Display` at the top left, so `Mouse::cell_in(&display)` maps a mouse event straight to a cell. `Parser::expect_cursor_position` / `take_cursor_position` handle the size reply, which is otherwise indistinguishable from Ctrl+F3.
- `cargo run --example paint`: a small paint program (strokes are joined into lines so fast drags leave no gaps, right button erases, 1-8 or scroll picks a colour).
- End-to-end scenarios for the paint example and the window size on Windows, Linux and macOS.
- `llms.txt`: a page for AI coding agents (what it is, when to use it and when not to, the API, easy mistakes, and a complete example). Its example is `examples/quickstart.rs`, which cargo compiles; `tests/llms.rs` checks the page against the API and the example against the file, and an end-to-end scenario runs the example in a real terminal.
- `terminal_graphics_interactive::prelude::*` brings in the graphics and interactive types together.
- `cargo run --example screensaver`: bouncing dots with fading trails (click adds a dot, any key quits). It shows the frame-timer loop: draw, handle input until the next frame is due, advance the animation.
- **Breaking (0.x):** pasted text now arrives as one `Event::Paste(String)` instead of key presses, using bracketed paste (the terminal is asked to wrap pastes in markers; `Terminal` turns it on and off). `Event` is no longer `Copy` and is `#[non_exhaustive]`, so a `match` on it needs a `_ =>` arm. Fixes right-click paste in terminals that paste on right click: pasting `cargo run ...` into `paint` used to press `c` (clear) and could press `q` (quit). Pastes over 1 MiB are cut. `paint` and `screensaver` ignore pastes.
- CI: a `publish` job releases to crates.io when `master` has a new version (token from the `CARGO_REGISTRY_TOKEN` secret; it warns and skips if the secret is missing). `.github` and `CLAUDE.md` are left out of the published crate.
- **Easy art API** (`art` module, in the prelude). `sketch(formula)` / `sketch_with(palette, formula)` fill the window every frame from a formula (a `Cell` with the column, the stretched row, the time and the mouse; return -1 to 1). `Palette` (`ocean`, `fire`, `rainbow`, `mono`, or `Palette::new`) turns numbers into colours using shade blocks for about 4x the steps. `World::new().balls(5).size(3.5).gravity(0.02).mouse_pulls().trails().run()` is a physics playground whose balls bounce off the walls and each other. Headless use for tests and benchmarks: `sketch_frame`, `World::simulation`, `Simulation`, `Pointer`.
- `Terminal::report_mouse_movement()` turns on pointer movement reporting with no button held (off by default: it is a lot of events over a slow link).
- New examples `plasma` and `balls`, benchmarks (`cargo bench --bench art`), `CONTRIBUTING.md` (how to add a palette, a setting or an example), and end-to-end scenarios for both examples on Windows, Linux and macOS.
- `llms.txt` has a section on making art, whose examples are the real `examples/plasma.rs` and `examples/balls.rs`.
- The design note is `docs/superpowers/specs/2026-10-17-art-api-design.md`.
- README rewritten: a short pitch with GIFs of the plasma and the physics world (a scripted mouse arrow and click rings drawn over the real examples), install, the examples, and how to add mouse and keyboard to anything. `tests/readme.rs` checks the GIFs exist and are real GIFs of a sensible size, every GIF is shown, and the README shows the real example files.
- `cargo run --release --example make_gifs` rebuilds `assets/*.gif`. It uses a pure Rust GIF encoder, a rasteriser, and a strict mini Rust interpreter (`examples/site/script`) that runs the real example sources and refuses what rustc would refuse (for example `cell.x * 2`). None of it is published to crates.io.
- **A website** with a live editor, built from Rust: `examples/web_art.rs` is the art engine compiled to WebAssembly (it runs the real example sources through a strict mini Rust interpreter, `examples/site/script`), `examples/build_site.rs` writes the page into `target/site`, and `examples/check_site.rs` loads it in a headless browser and drives its buttons, editor and mouse (`--require` fails if no browser is found). `.github/workflows/pages.yml` builds and checks the site on every pull request and deploys it to GitHub Pages when `master` changes (Settings, Pages, Source = "GitHub Actions"). Examples `rings`, `tunnel`, `waves` and `bubbles` join the gallery.
